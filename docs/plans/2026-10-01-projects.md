# Issue #7 source audit and implementation

The issue requires workspace-based Hermes membership; a session Project foreign
key is neither present nor needed. This replaces the earlier browse-only preview.

Independently inspected installed `/opt/hermes` and the exact compose source,
`3632f9173d218fd24f3fa595d7affa159b0774cd`, unpacked at
`/opt/data/profiles/developer/cache/scratch/hermes-pin-3632f917`:

- `apps/shared/src/gateway-contract.generated.ts` and `.openrpc.json`, plus
  Python contracts in `tui_gateway/contracts/{projects_pets,sessions,prompt_voice,
  config_free_tier_control}.py`. The pin accepts `cwd_explicit`; the installed
  source has since removed that parameter. ChatHermes sends the pinned field and
  falls back only on its precise extra-field schema rejection when cwd exists.
- Desktop `apps/desktop/src/store/projects.ts`: `projects.tree` for the
  overview, `projects.project_sessions` for fully hydrated repositories/lanes;
  profile and generation checks prevent late results entering another scope.
- Desktop `app/session/workspace-session-target.ts` and
  `app/session/hooks/use-session-actions/index.ts`: capture the workspace owner,
  resolve with `config.get {key: 'project', cwd, profile}`, and create with
  `source: 'desktop'`, cwd, `cwd_explicit`. Opening a Project is UI scope only.
- `tui_gateway/methods_config.py` and `project_tree.py`: grouping is owned by
  Hermes, including Git identity, external worktrees, automatic repositories,
  and synthetic Home. Auto Project IDs are literal repo paths, so the plugin
  transports IDs in query parameters rather than path segments. Tree overview lanes omit sessions; drill-in hydrates them.
- `methods_session.py`, `session_workdir.py`, and `server.py`: create returns
  separate runtime/stored IDs; empty drafts persist on first prompt. Native
  resume restores the stored workspace. `source: 'desktop'` follows Desktop's
  supported context/runtime behavior. No Project ID is accepted on create.
- `rpc_dispatch.py`, `transport.py`, `ws.py`, `session_transports.py`, and
  `change_watcher.py`: reuse the dashboard dispatcher, profile admission and
  transport fanout. The transport must expose `_closed` for Hermes reapers.
  Start the native change watcher and forward `projects.changed` and
  `sessions.changed`; its signatures include served profile stores.
- `gateway/platforms/api_server.py`: REST creation ignores workspace fields and
  REST turns on this pin do not restore workspace cwd. Project chats therefore
  use the native `session.resume`/`prompt.submit` flow, adapted into the existing
  ChatHermes SSE/transcript/composer interface through authenticated Python
  routes. Ordinary REST chats retain their existing routes.
- `agent/prompt_builder.py`: context discovery belongs to the runtime. The
  plugin never injects `.hermes.md`, AGENTS, CLAUDE or Cursor content.

Implementation retains only selected Project/session IDs, current gateway
responses, and ephemeral transport-route markers. It does not directly write native
Project/session databases, classify cwd paths, or mutate active Project state.
New chats re-read the authoritative node, choose its path then first repo path,
resolve under the captured profile, and call normal `session.create`. Missing
paths are rejected when the pin falls back to an unrelated launch directory.
Existing sessions resume without any cwd parameter. Workspace model selection
uses the provider inventory and session-only `config.set`; REST model-route
aliases remain available for ordinary REST chats.

Project management and moving sessions are outside this focused first workflow;
Hermes Desktop/CLI continue to own those operations. Their changes appear through
native change events. No source/base-image pins or personal homes are changed.
No commit or push is requested or performed.

A native event subscription also holds the selected workspace session as a
viewer, keeping live empty drafts alive beyond the 20-second disconnect grace.
Transport teardown uses Hermes's standard fanout cleanup, preserving other
viewers. The visual regression composes for 22 seconds before its first send.
Opening a scope presents its Project screen while retaining the previous chat
state; new-chat actions target the scope, and resume always targets the stored
session without changing its workspace.

Hermes's compact resume projection deliberately omits most tool output. Persisted
workspace chats therefore reuse the existing authenticated, paginated REST history;
unpersisted drafts alone fall back to native resume messages. This keeps full
completed disclosures available while runtime turns still use the cwd-aware RPC.
