# Issue #7 implementation and verification

## Outcome

The earlier browse-only preview is replaced by workspace-based Projects support.
Hermes's gateway RPCs are authoritative; no Project foreign key or parallel plugin
membership store is needed. The source audit is in
[the implementation plan](../plans/2026-10-01-projects.md).

- Projects list uses `projects.tree`, retaining automatic repositories, Home,
  counts, hierarchy and scoped session IDs. Path-valued automatic IDs travel as
  encoded query parameters. Selected Projects use `projects.project_sessions`;
  only their hydrated sessions are flattened for display.
- Opening a Project presents its scope without changing the previous session's
  workspace. New chat re-reads the node, chooses path then first repository path,
  resolves with `config.get` under one captured profile, and calls normal
  `session.create` with `source: 'desktop'`, resolved cwd and `cwd_explicit: true`.
  No `project_id` is passed to create. Pathless Projects and unrelated missing-path
  fallbacks fail before creation; Home creates a normal no-Project draft.
- Workspace sessions use native `session.resume`, `prompt.submit`, image bytes,
  and session-only model selection. Python routes adapt native events into the
  existing client/chat components. Resume never supplies a cwd override. Native
  context discovery, tool execution and stored IDs remain Hermes's responsibility.
- Native Project/session change events, reconnect, foregrounding, completion and
  profile changes refresh the tree and hierarchy. A session viewer on the event
  subscription keeps empty native drafts alive while composing, including past
  the native 20-second disconnect grace. Unmount/profile/session changes use
  native fanout teardown and preserve other viewers.

The repository was clean at the start. Existing ignored local configuration is
preserved. No commit, push, source pin change, base-image change or personal-home
mount is performed. Built assets are regenerated under
`plugin/chathermes/dashboard/dist/`.

## Limits

The runtime/model tests use the deterministic OpenAI-compatible fixture; no
external paid model or real credentials are used in this turn. The separate real
LiteLLM integration script has been updated but is not claimed as run. A launched
Hermes Desktop client, physical camera, iOS keyboard/zoom behavior, and actual
Git worktree/SSH/container workspace round-trips are not exercised. Worktree
membership is covered by the authoritative hierarchy adapter test, rather than
a frontend cwd classifier.

Project management and session moves remain in Desktop/CLI for this focused
initial workflow. Workspace chats use provider inventory models; ordinary REST
chats retain gateway model-route aliases. Approval/clarification actions remain
in Hermes, following the existing plugin's locked-send behavior.

Compatibility is verified against the exact pin. The separately inspected newer
installed source has removed `cwd_explicit` from its generated create contract.
Workspace creation sends the field first; for older versions, only the exact
`cwd_explicit` extra-input schema rejection triggers a retry without the field,
and only for an existing local cwd. Other gateway failures are not retried.
Backend upgrades require checking these native RPC/transport contracts again.
