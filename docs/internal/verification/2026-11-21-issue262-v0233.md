## Established reconnect root cause and repair

The second uninterrupted full run finished **190 passed, 1 failed, 1 skipped in
34.1m, exit 1** (`clean-integration.log`). All four delegated approval cases
passed. Its output is preserved in `clean-integration-output/`.

The diagnostic command repeated only mobile memory reload ten times:

```sh
npm run test:integration -- tests/workflows/memory-context.spec.ts --grep 'native deltas omit split blocks' --project=mobile --repeat-each=10
```

Before the repair it produced **9 passed, 1 failed in 2.4m, exit 1**
(`memory-reload-diagnostic.log`, `memory-reload-diagnostic-output/`). The failing
repeat4's `synthetic-memory-observations.json` proves the boundary error:

1. The new socket received native delta seq 19, `ut. Trea`, before its first
   resume reply.
2. That reply's snapshot ended `NOT new user inp`; the later activation
   snapshot ended `NOT new user input. Trea`.
3. The client discarded the pre-reply delta, kept the older snapshot and ignored
   the newer activation snapshot while running. It appended seq 20, `t as aut`,
   producing `NOT new user inpt as aut` in the rendered mutation samples.
4. The native terminal text was intact. This establishes a client recovery gap;
   the native producer and exact-note suppression grammar were not malformed.

`native-gateway.ts` now buffers pre-reply events. For an active text snapshot,
`native-recovery.ts` matches its exact prefix against a contiguous retained native
turn from the existing `session.events.since` method. It verifies process epoch,
runtime/profile ownership and actual sequence records; it uses the observed turn
boundary rather than matching repeated prose by suffix. Only records proven
covered by that prefix/replay page are deduplicated. `latest_seq` is never used
as an applied watermark, and arriving frames beyond the actual page remain live.
Changed epochs, inconsistent records and foreign scopes fail closed with a generic
recovery error. An explicitly evicted prefix with verified scope withholds only
unverifiable assistant prose until the terminal reply, keeping controls connected.
The native cache is bounded; this does not turn
the legacy protocol into generally lossless replay or durable execution.

## Continuation: independently identified snapshot turn race

The continuation preserved the intentional tracked and untracked work on
`maintenance/issue-262-v0233`. No upstream files, commits, staging, pushes,
deployments or unrelated Docker resources were changed.

The reviewer's race reproduced before the fix: `race-regression-before.log`
records two failing protocol regressions. With no observed session frame, a
resume snapshot contains turn A's `Same`, but replay already contains A's
completion and turn B's start. B's `Different` produces a false recovery failure;
B's `Same` falsely succeeds against B. An observed frame alone also cannot prove
which turn an earlier snapshot captured. Text equality is not identity.

The pinned runtime trace explains the race. In `tui_gateway/session_registry.py`,
`_live_session_payload` copies `_inflight_snapshot` under `history_lock`; the
inflight wire object has no event sequence or turn ID. `session.activate` calls
that payload builder (`methods_session.py`). In `event_replay.py`, `events_since`
copies retained event records under the independent replay lock, and
`session.events.since` reads `latest_seq` separately after obtaining that page.
`prompt_turn.py` appends inflight deltas under `history_lock` before emitting
`message.delta`, emits `message.start` before agent streaming, and emits
`message.complete` before releasing the turn and admitting continuations. The
snapshot and later replay therefore cannot be joined by "latest start" or by
matching prose, and `latest_seq` is not a snapshot watermark.

Recovery now reads replay before a fresh activation snapshot, then reads replay
afterward. It validates both reads' epoch, runtime/profile scope and ordered
records, requires the earlier actual record to survive unchanged in the later
page, and requires a complete contiguous live turn with no completion or new
start across the bracket. Only that independently identified turn may supply the
snapshot's exact delta boundary. Absent pre-snapshot evidence, explicit anchor eviction or an intervening turn
withholds unverifiable prose and preserves controls; scope/epoch/record
inconsistencies (including an unexpectedly missing retained anchor) still fail closed. Arriving records beyond the proven replay
page remain live. The fresh activation snapshot replaces the original resume
snapshot even when still running.

The 57 focused protocol regressions passed (`race-focused-final.log`). They
cover both identical/different new-turn text without an observed frame, controls
