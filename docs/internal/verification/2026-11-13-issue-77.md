## Pinned-runtime and verification limits

The wire schema rejects draft `cwd` discovery fields: project-local skills cannot
be suggested before session creation. The UI explains its profile-level draft
catalog and execution resolves in the created Project workspace. Four legacy
dynamic argument providers (`skin`, `personality`, `tools`, `handoff`) run outside
profile scope; their argument completion is withheld with an explanation.
Catalog visibility alone does not assert execution support; terminal/client-only
commands remain labeled and refuse safely. These boundaries are documented in the
maintained API and user guides.

Native retry may persist an untyped system wrapper for a skill; the reviewed
Desktop projection hides it. A retried answer may therefore lack a visible saved
user bubble. Compression likewise owns the replacement transcript. ChatHermes
preserves native history and does not fabricate durable replacement messages.

Desktop Chromium and Chromium mobile viewport checks do not verify real Android
or iOS software keyboard/IME behavior, native installation, or real push delivery.
No real-provider tests were run. Registered-plugin routing/profile filtering and
fault/stale-response cases have focused frontend coverage; the live slash workflow
seeds skills, bundles, quick commands and aliases, not a new command plugin.
