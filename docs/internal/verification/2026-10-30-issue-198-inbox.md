## Audit before implementation

The issue requirements were checked against `database.py`, `execution_viewer.py`,
`completion_outbox.py`, `artifact_indexer.py`, the dashboard router, Vue shell,
navigation/link validation, API client, and the documented architecture/API/testing
contracts. Native behavior was checked against the reviewed Hermes source pin
`bf0203a794a07aac3ff764972ab9087baa4e4f4e` in this worktree's ignored
`.hermes-source` checkout.

There was no Inbox schema, API, route, navigation, read state or history collector.
Native retained viewers already captured committed completions and native
approval/clarification/secret requests for push. Artifact indexing provided an
existing accessible-profile enumeration contract and startup/shutdown pattern,
but did not create notifications. Global native transports only receive global
broadcasts; session requests require native request snapshots or retained viewers.
The pin supplies profile-aware live-session matching, open-request snapshots,
per-session event sequences, read-only profile histories, message UIDs and
incremental row reads. Connector request identity is `op_id`, not `operation_id`.

Baseline: `npm test` passed 991 tests. The focused backend baseline initially
passed 239 tests with six profile skips while the Hermes source was unavailable;
after preparing the exact pin it passed 245 tests and failed one existing viewer
fixture. That fixture replaced the parent `websockets` package before its

## Session-opening deletion follow-up

The follow-up replaces the incomplete permanent session-deletion cache with
repeatable checks after every successful chat navigation, live final assistant
message and native reconstruction/reconnect. Visible count refreshes also check
the open session, covering records collected after the live event. Checks page
through the owning profile's read and unread notifications and delete exact
profile/session matches. Checks for the same session run sequentially so a new
completion during an earlier deletion gets another lookup. Failed requests remain
retryable, and navigation/unmount or failed native attachment prevents deletion.

Each check republishes the current session to the push worker. The worker's
existing fresh visible-client handshake and exact profile/session/run comparison
remain authoritative. The incomplete unused worker helper, which could close
notifications without verifying visibility, was removed; the worker source now
matches HEAD. Scheduled notification behavior is unchanged.

The reproduced push-worker failures came from a changed default harness client URL
and an invalid new assertion: opening default/two cannot close alpha/one. Restoring
the stale outer client URL preserves the handshake tests and scheduled new-window
expectations. The replacement test navigates from Inbox to the exact session and
checks that other profiles and sessions remain open. The full worker suite passes.
